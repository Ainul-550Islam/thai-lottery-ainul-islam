## 2. Per-file change rationale

1. **`config/fees.php`** — gap closure. Was a 14-row flat catalogue with two generic rows; is now the complete grouped, provider-aware schedule with the full row contract (stable key, label key, group, calculation, exact decimal amount/rate, currency, enabled, public_visible, internal, provider, effective_from/to, rule_version, description_key, min/max, execution mapping), a triple-guarded internal row for production suppression proofs, and a `never_public` guard.
2. **`config/finance.php`** — gap closure (finance drift). `deposit.fee_percentage` / `withdrawal.fee_percentage` were hardcoded `'0.00'` while `fees.php` read env vars the engine ignored — display could drift from execution. Both are now driven by `FINANCE_DEPOSIT_FEE_PERCENTAGE` / `FINANCE_WITHDRAWAL_FEE_PERCENTAGE`, the same env vars the public schedule mirrors, so one knob moves both.
3. **`config/payment.php`** — gap closure (provider mapping). Adds the `public_fees.providers` bridge: stable public provider keys → live PaymentMethod (`bank → bank_transfer`) vs schedule-only providers, with provider *identity* only — no credentials, no secrets.
4. **`PublicServicePagesController`** — gap closure. Now composes grouped sections for the page, exposes the same grouped projection through the JSON API, and adds the `feesPreview` endpoint that delegates 100% of logic to the service and returns the DTO projection. No fee logic or arithmetic lives in the controller.
5. **`FeePreviewRequest`** — new. Whitelist validation (category from the live public rows, provider from the payment-layer keys), strict decimal `base_amount` (no exponent/sign/separator, length-capped), cross-field provider/family rule, and **no fee field exists at all** — client fee amounts cannot enter the pipeline.
6. **`FeesPageService`** — gap closure, the core. Grouped ordered projection, provider-aware rows with labels, runtime **live-rule mirroring** through `execution` config paths (whole-percent → fraction via bcmath), effective-date filtering (exclusive end), NOT_CONFIGURED states, `calculateResult()` returning the immutable DTO, documented scale-2 half-up rounding policy, deterministic output, no floats anywhere. All original public methods (`categoryOrder`, `publicFees`, `calculate`) keep their contracts.
7. **`Money.php`** — audited, unchanged: already refuses floats, requires bcmath, rejects precision loss. No change necessary.
8. **`DepositService`** — supporting dependency: the nine-question fee-path audit documented on `resolveFee()` (rate source, canonicity, single calculation, persistence, balanced posting, historical snapshot, replay safety, client-tamper safety, provider mapping). Live economics untouched.
9. **`WithdrawalService`** — same audit; live economics untouched.
10. **`PaymentInitiationService`** — audit note: fee comes exclusively from `DepositService::resolveFee()`, recorded twice as *data* (deposit row + mirrored on the payment aggregate) but **charged once** (completion credits the stored net).
11. **`WithdrawalDisbursementService`** — audit note: resolves a gateway driver, never a fee; reads only the stored snapshot; Completed withdrawals refuse re-dispatch.
12. **`LottoDiscountService`** — audited, unchanged: reads only `discounts.*` config, refuses immutable GLO products with `GLO_PRICE_IMMUTABLE`. Fee configuration cannot reach it. Regression asserted in the new parity suite.
13. **`FeeCalculationResult`** — new immutable DTO: category, provider, base, fee, currency, calculation, rule version, configured state, display form, effective window; `toArray()` whitelisted projection.
14. **`PaymentMethodData`** — supporting: `feePercent()` (exact integer bps→percent math) and `toPublicArray()` (explicit non-secret projection).
15. **`PaymentMethodConfig`** — supporting: `metadata` hidden from serialization (leak closure) + `publicFeeProjection()`/`feePercent()` whitelisted helpers.
16. **`Withdrawal`** — supporting: documented fee-snapshot semantics + `feeMoney()`, `netAmountMoney()`, `appliedFeeRateFraction()` reading the frozen request-time values through Money.
17. **`fees/index.blade.php`** — gap closure: six grouped sections (Account / Balance Transfer / Withdrawal / Cash In / Agent / Yearly Maintenance), server-rendered preview widget with server-whitelisted options, global footer note. Escaped output only.
18. **`fee-table.blade.php`** — gap closure: conditional provider column, per-row `data-pp-state`/`data-pp-provider`/rule-version, visually-hidden provider-none label, semantic `<table>/<caption>/<thead>/<tbody>/th scope`.
19. **`account-services.css`** — supporting: provider cell, rule-version, preview widget styles; existing responsive/reduced-motion rules retained.
20. **`public-pages.js`** — supporting: optional preview enhancement — POSTs to the API and renders the **server's** answer via `textContent`; no `innerHTML`, no client-side math, graceful 4xx/429 handling.
21/22. **`lang/{en,th}/account_services.php`** — gap closure: group labels, provider labels, 17 new category labels, 27 description keys, preview widget labels, state labels, provider-none a11y label — identical key sets (asserted by tests).
23. **`routes/web.php`** — audited, unchanged: `GET /fees` anonymous + `public.legal`, ordering intact.
24. **`routes/api.php`** — gap closure: `POST /api/v1/fees/preview` (anonymous + `throttle:api`, same pattern as the public fees GET) inside the existing v1 group.

Rows without a live lane are a configured public schedule with **zero** transaction side effects — nothing in the finance engine reads them.

## 7. Fees intentionally NOT wired into live execution

Every row except the four execution-mirrored ones (generic/bank withdrawal, generic/bank cash-in) has **no runtime execution mapping**, deliberately: `account_renewal`, `account_verification`, `referral`, `affiliation`, all five transfer rows, `withdrawal_skrill/neteller/paypal/perfect_money`, `cash_in_skrill/neteller/paypal/perfect_money`, all five agent rows, `maintenance`. Their values are public configuration only; inventing transaction side effects for them was out of scope and unsafe. The two PayPal rows stay **NOT_CONFIGURED** (unspecified percentage — never guessed).

## 4. Security verification

- **Secret exposure**: payment gateway credentials (`payment.gateways.*` secrets) are never read by the fees surface; `PaymentMethodConfig.metadata` is now hidden from serialization; tests inject fake live secrets and assert their absence from `/fees`, `/api/v1/fees`, and every preview response. No internal IDs, no margins (the internal margin row is triple-guarded and proven absent), no raw env values, no SQL/stack traces.
- **Client fee tampering**: `FeePreviewRequest` has **no fee field**; tests send `fee`, `fee_amount`, `rate`, `currency`, `rule_version`, `state` and assert every one is ignored. Deposit/withdrawal HTTP layers pass only `ip`/`payout_details` — no fee can reach `resolveFee()` from a request body.
- **Duplicate charging**: deposit fee computed once at request, persisted, completion credits the stored net (idempotency-keyed); withdrawal fee frozen at request, completion debits the stored gross once, Completed withdrawals refuse re-dispatch; replay tests prove one row/one fee after idempotent retries. The reconciliation bug that would have mis-flagged fee-bearing deposits as CRITICAL was found and fixed, with all 34 original reconciliation tests still green.
- **Decimal math**: `FeesPageService` is bcmath-only with a documented scale-2 half-up policy (intermediate scale 4, single rounding); source-scan tests assert no `floatval`/`(float)`/native `round(`; the new `feePercent()` helpers use exact integer math (no float even as a bcmath-free fallback).
- **Routes/middleware**: `GET /fees` anonymous + `public.legal` (unchanged); `GET /api/v1/fees` anonymous + `throttle:api` (unchanged); `POST /api/v1/fees/preview` anonymous + `throttle:api` with whitelist validation, strict decimal regex (no exponent/sign/separator), length caps, provider/family cross-validation, and a 422 (not 500) catch-all. Throttling proven by test (429 after the configured limit).
- **GLO boundary**: immutable L6 (80.00 THB) / N3 (20.00 THB) prices asserted unchanged before and after fee config changes; `quote('glo_l6')` still refuses with `GLO_PRICE_IMMUTABLE`; full GLO suites green.
