## Implemented in this increment

Original Cash/Win accounting now gates exact settled replay and separately authorized reversal. Current locking reads defeat an old repeatable-read conversion/source snapshot. The original transaction, full journal, historical snapshots, chart and bounded reciprocal inverse must agree. New writes are proved before success/quote consumption; reversal proof runs after linkage as well. Conversion-only explicit NULL system-leg posting preserves the existing identities of unrelated writers. No existing assertion or refund-admission gate is removed.

The complete numbered delivery continues after File1284. All changed production, test, CI, inventory, runbook and acceptance bodies are delivered in full, together with a cumulative distinct-path source archive and SHA256 manifest. Dependencies, secrets, generated assets, native binaries and disposable databases are not application source deliveries.

## Historical accounting review is explicit

Pre-Part64 conversion fee entries may contain the transaction wallet or an account-balance snapshot rather than the canonical NULL system-leg identity now required. Those originals fail closed. No SQL backfill, history adoption, destructive repair or comparison with today's wallet balances is provided. Production rollout must inventory affected originals read-only, establish independent original evidence, approve any remediation policy, rehearse it on a populated isolated restore, and separately review the resulting accounting before allowing those historical operations. This is not fulfilled by an empty migration rehearsal.

## User-deferred provider setup

The user will supply merchant/provider and production details later. Live transfers remain disabled until actual merchant onboarding, authorized credentials, endpoint-specific signatures, destinations, funding, reconciliation, limits and incident procedures are configured and independently tested. Local synthetic Stripe proof is not a refund POST or a real bank/card transfer. There is no invented operator approval, provider licensing or worldwide legal permission.

## Broader boundaries

- Part64 is independent-source structural proof, not resistance to a writer able to rewrite every conversion, transaction, journal and snapshot coherently.
- Same-currency Cash/Win movement is not foreign exchange. Unknown external events, other currencies and arbitrary global debt remain separate risk work.
- All historical unbound or anonymous holds and accounting records remain unadopted. A new writer integration requires its own reviewed ownership, original identity, authorization and rollback boundaries.
- The existing actor/permission model remains authoritative; Part64 does not certify every policy writer, staff-session revocation race or cross-host deployment.
- Real production database restore/upgrade rehearsal, production load and deadlock qualification, private evidence retention/access review, external reconciliation and disaster recovery remain deployment tasks.
- Country-by-country permitted gambling/payment operations, AML/KYC, sanctions, privacy, tax and consumer obligations require actual licensed human approval. Application source and test totals cannot grant it.
